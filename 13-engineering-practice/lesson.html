1 anomalib:工业落地的瑞士军刀

课程里讲过的无监督方法,绝大多数不需要你从论文开始复现。OpenVINO 团队(Intel)维护的开源库 anomalib,把 PatchCore、PaDiM、FastFlow、EfficientAD、DRAEM、WinCLIP 等主流方法全部做成了开箱即用的实现,而且共享同一套 API:数据模块(datamodule)+ 模型(model)+ 引擎(engine)三件套。换方法 = 换一行代码,这让"多跑几个方法对比再定"从奢侈变成日常。

第一步,安装(注意版本:本课代码按 anomalib v1.x 编写,细节以官方文档为准):

# anomalib v1.x,Python 3.10+(版本与依赖细节以官方文档为准) pip install anomalib # 训练依赖 PyTorch;首次运行会自动下载预训练骨干网络权重

第二步,在 MVTec AD 上训练一个 PatchCore——第 8 课的主角,不到十行:

# anomalib v1.x,Python 3.10+;API 以官方文档为准 from anomalib.data import MVTecAD # 数据模块:自动下载/组织 MVTec AD from anomalib.models import Patchcore # 第 8 课的 PatchCore,开箱即用 from anomalib.engine import Engine # 统一封装训练 / 评估 / 推理 datamodule = MVTecAD(category="bottle") # 15 个类别,先拿 bottle 练手 model = Patchcore() # 换方法只改这一行:Padim() / Fastflow() / EfficientAd() / Draem() engine = Engine() engine.fit(model=model, datamodule=datamodule) # "训练":抽特征、coreset 采样、建 memory bank engine.test(model=model, datamodule=datamodule) # 输出图像级 / 像素级 AUROC 等指标

第三步,推理与导出。工控机上通常不跑 Python 训练环境,把模型导出成 OpenVINO / ONNX 格式,交给部署侧的推理引擎:

# 推理单张图,并导出 OpenVINO 用于边缘部署(以官方文档为准) from anomalib.deploy import ExportType preds = engine.predict(model=model, data_path="my_part.png") # 预测结果包含:异常分数 pred_score、热力图 anomaly_map、判定 pred_label engine.export(model=model, export_type=ExportType.OPENVINO) # 换自己的数据:把 MVTecAD 换成 Folder 数据模块, # 指定 normal_dir="正常样本文件夹" 即可,其余代码一行不动
落地节奏:先复现,再换数据

推荐的动手顺序:先在 MVTec AD 上原样跑通,确认环境、指标都对(PatchCore 在多数类别上图像级 AUROC 应到 99% 上下)——这一步排除掉一切环境问题;然后只换数据模块,把 MVTecAD 换成指向你自己文件夹的 Folder,其余不动。任何时候出了问题,你都知道变量只有一个:数据。

2 选型决策树:四个问题定方法

方法选型听起来玄,其实骨架就是四个问题,按重要性排序:① 数据可得性(有没有缺陷标注?有没有正常样本?)→ ② 输出粒度(要不要像素级轮廓?)→ ③ 时延预算(几毫秒还是几十毫秒?)→ ④ 内存与样本规模。数据问题永远排第一——它直接决定你能走哪半张地图;后面三问只是在可行集合里挑最合适的。

下面这棵决策树不是让你看的,是让你答的。把你产线的真实情况代进去,一路点下来,终点是一张推荐卡:方法、理由、对应课次、anomalib 里的模型名。选错了没关系,「重新开始」随时重来——真实的选型本来就要多走几遍。

每答一题,下一问滑入;走过的路径会留在上方,方便回看你是在哪一步被分流的。
立场先亮明:默认答案是 PatchCore

这棵树的走向背后有一个明确立场:如果没有硬约束把你推向别处,先选 PatchCore(第 8 课)。理由:只要正常样本、零训练、自带像素级热力图、MVTec AD 上 ~99% AUROC、anomalib 一行即用——它是"精度 / 数据要求 / 工程复杂度"三角里最均衡的点,也是工业界事实上的基线。其他路线都是在回答"什么时候不选 PatchCore":时延卡到毫秒级 → EfficientAD;内存紧或样本上万 → FastFlow(参数化,不建库);有标注且要监督精度 → YOLO / U-Net;什么样本都没有 → WinCLIP 先顶上。

3 阈值:从分数到判决

课程里所有无监督方法输出的都是异常分数——一个连续值。但产线要的是判决:这个工件,放行还是报警。从分数到判决,中间隔着一个阈值,而阈值怎么定,是离线指标和上线效果之间最常见的断裂带。

上线之前:在验证集上选阈值

第 4 课的方法论直接搬来用:准备一个带标签的验证集(正常 + 各类缺陷都要有),扫描候选阈值,按业务目标选:

  • 最大 F1:误杀与漏检同等看待时,取 F1 最高的阈值——本课练习 TODO 2 就是它;
  • 按误杀率上限反推:更贴近产线的定法。业务说"误杀率不得超过 1%",就在验证集上找到恰好满足这条线的阈值,漏检率是多少就接受多少——阈值是业务约束的产物,不是模型的属性。

两个容易踩的工程细节

  • 分数归一化漂移:很多实现会把异常分数按训练/验证集的最小最大值归一化到 0-1。一旦换了数据重建了库,归一化基准就变了——0.5 这个数字在两次部署里含义完全不同。阈值必须和产生它的那套分数基准绑定存档。
  • 按产品型号分阈值:不同型号的工件,正常分数分布天然不同。A 产品调好的阈值直接用到 B 产品,大概率不是误杀爆炸就是漏检成筛子——一个型号一套阈值,写进配置而不是写进代码。

上线之后:阈值不是一劳永逸

最隐蔽的坑在上线之后。模型权重不会自己变,但输入分布会:换了一批原料、镜头脏了、车间灯管老化、季节光照变化——正常样本的异常分数整体抬高,老阈值就开始成片误杀;反过来分布下移,则悄悄漏检。这叫分布漂移,它不报错、不崩溃,只在质检报表上慢慢显形。

对策是把分数分布本身当成被监控对象:上线时留存一段"基线分数"(确认正常时期的分数),之后持续对比近期分数与基线:

# 漂移报警的最小实现(本课练习 TODO 4 会亲手写) 报警条件:mean(近期分数) > mean(基线分数) + 3 × std(基线分数) # 均值越过基线 3σ → 分布大概率变了:先查相机/光照/原料, # 再用近期数据重新标定阈值;都救不回来才考虑重建库/重训

注意这个顺序:漂移报警的第一动作是查环境、重标定阈值,不是立刻重训模型。大多数漂移是光学和物料层面的,把镜头擦干净比重训便宜一万倍。

4 部署考量:速度、边缘与三件比模型更重要的事

速度量级:先对齐数量级,再谈优化

选型时不需要记精确毫秒数,记住量级排序就够(以下为量级示意,随硬件、分辨率、实现变化很大):

EfficientAD:~1-5ms

轻量学生网络,为在线全检而生。

毫秒级预算下基本是唯一解(第 9 课)。

FastFlow:~10-40ms

骨干抽特征 + 流模型算似然,参数化前向。

速度与内存都不随样本数增长(第 11 课)。

PatchCore:~30-100ms

要在 memory bank 里做最近邻检索,耗时取决于库大小。

coreset 采样率是速度旋钮(第 8 课)。

边缘部署一句话:训练侧用 PyTorch,部署侧把模型导出为 ONNX / OpenVINO(§1 的 engine.export),交给工控机或边缘盒子的推理引擎跑——这一步 anomalib 已经替你打通。

比模型更重要的三件事

产线项目失败,败在模型的其实是少数。下面三件"光学与机械"的事,任何一件没做好,换什么模型都救不回来:

① 分辨率匹配缺陷尺寸

要检的最小缺陷,在图像里得占足够多的像素(经验上至少几个像素宽)。0.1mm 的划痕配 2 个像素,神仙模型也检不出——先算光学放大倍率,再谈算法。

② 光照稳定性

打光是玄学也是科学:同一道划痕,顺光下不可见、侧光下刺眼。光源要恒定(遮环境光、用频闪同步),否则光照变化本身就是最大的"异常"来源,§3 的漂移报警会先于缺陷响起来。

③ 工件定位一致性

第 8 课讲过 PaDiM 逐位置建模、对对齐敏感——工装夹具把工件摆到同一位置、同一角度,比给模型加对齐模块便宜且可靠。位置乱飞的产线,先修机械再修算法。

5 常见翻车 checklist

下面五条,每一条都是真实项目里反复出现的事故模式。上线前对着清单过一遍,便宜且救命——格式统一为"症状 → 病因"。

① 离线指标好得可疑 → 测试集泄漏
同一个工件拍的多张照片,被随机划分进了训练集和测试集(第 3 课的老坑)。模型"认得这个工件"而不是"懂缺陷",AUROC 虚高。划分必须按工件/批次切,不能按图片切。
② 某类缺陷成片漏检 → 训练集里混入了缺陷样本
one-class 方法的隐形杀手:训练集号称"全正常",实际混进了没被发现的缺陷品。模型认真地把这类缺陷学成了"正常"(进了 memory bank / 被学生网络拟合),同类缺陷分数被拉低——而且离线指标上很难第一时间看出来。建库前的数据要人工复核,宁可少不可脏。
③ 新产品上线误杀/漏检失控 → 阈值跨产品复用
A 产品调好的阈值直接搬给 B 产品。不同型号的正常分数分布天然不同(§3),阈值必须每个型号在各自验证集上重新标定,并与分数归一化基准一起存档。
④ 离线 AUROC 很高,上线误杀爆炸 → 域漂移 / 阈值失配
离线数据和产线实况不是同一个分布:光照、镜头、物料批次都变了(§3 的分布漂移),或者阈值定在了离线分数基准上。先比对线上分数分布与离线基线,重标定阈值;必要时用产线现场数据重建正常库。
⑤ 指标全绿却总在错的位置报警 → 只看图像级分数,不看热力图
图像级分数对了,不代表定位对了:模型可能因为边角的反光把图判成异常,"分对了,理由是错的"。这颗雷平时不响,分布一变就炸。验收时抽样核对热力图与真实缺陷位置(第 4 课的 PRO 指标就是干这个的),别只看 AUROC。

6 前沿方向:这个领域正往哪走

收官之前,把四个正在发生的方向各用一段讲清楚——不吹,只说它们分别补上了课程方法的哪块短板。

逻辑异常:零件都好,装配错了

课程里的方法都在回答"这块长得正常吗",但有一类缺陷每个局部都完美:螺丝少了一颗、保险丝插错了槽、数量不对、顺序颠倒。MVTec 为此专门发布了 MVTec LOCO 基准,把异常分成结构异常(划痕、污染)与逻辑异常(成分、数量、位置的约束被破坏)。patch 级"查词典"对后者无能为力——需要成分级的全局理解。GCAD 一类的思路是双分支:局部分支照旧抓结构异常,全局分支学习"这张图该由哪些成分、以什么布局构成",装配错误在全局分支现形。

3D 缺陷检测:深度里藏着 RGB 看不见的

同色的凹陷、平面度超差、深度方向的变形——灰度和颜色完全正常,只有几何变了。MVTec 3D-AD 基准为此提供 RGB + 点云/深度数据,方法上大多是把课程里的套路(重构、特征嵌入、师生)搬到深度模态,再做 RGB 与 3D 的融合。如果你的产线在检结构件的形位公差,这条线值得跟。

多类统一模型:一个模型管所有产品

课程里的 one-class 范式默认"一个类别一套模型":15 种产品就是 15 套权重、15 套阈值、15 份维护成本。NeurIPS 2022 的 UniAD 证明一个 Transformer 模型可以同时学所有类别的"正常",精度接近单类模型——代价是要专门抑制"恒等捷径"(模型学会原样复读输入,重构误差失效)。对多产品小批量的工厂,维护成本直接除以 N,这条线的工程价值非常直接。

基础模型持续渗透:第 12 课的延长线

WinCLIP / AnomalyCLIP 只是开头:SAM 把"分割一切"的能力带进缺陷轮廓提取,多模态大模型开始能用自然语言描述缺陷、生成质检报告。冷启动会越来越便宜,"文字定义缺陷"会越来越可用。但落地判断标准不变,还是第 4 课那三问:数据从哪来、指标怎么算、时延扛不扛得住——新模型只是给这三问换了答案,没有取消这三问。

✓ 自我检验

四道题,全部是"产线上真会遇到"的判断题。

Q1 · 手头只有 200 张正常样本、没有任何缺陷标注;需要像素级热力图辅助复检;时延要求宽松。选什么?
✔ 正确。走一遍 §2 决策树:没有缺陷标注 → 有监督出局;正常样本管够 → 轮不到零样本兜底;时延宽松、常规内存 → 落在默认答案 PatchCore(第 8 课):零训练、像素级热力图、MVTec AD ~99% AUROC。
✘ 回到 §2 的决策树亲手点一遍:第一问"有缺陷标注吗"就把 YOLO 挡在门外;而正常样本明明管够,放着 one-class 主力不用去选精度有限的零样本(WinCLIP 是"什么都没有"时的过渡方案),是把兜底当了主力。答案是默认选项 PatchCore。
Q2 · 产线要求毫秒级在线全检,时延预算 < 5ms。选什么?
✔ 正确。§4 的速度量级表:EfficientAD ~1-5ms,是 5ms 预算下基本唯一的选项(第 9 课);PatchCore 要查 memory bank,几十毫秒量级;U-Net 是有监督路线,这里也没提有标注。硬时延约束一出现,决策树(§2 第 ④ 问)直接分流。
✘ 回看 §4 的速度量级表:PatchCore 的最近邻检索几十毫秒起步,挤不进 5ms;U-Net 需要像素级标注且这里没有。毫秒级预算下只有师生蒸馏路线的 EfficientAD 满足——这正是 §2 决策树把"时延预算"单独列为一问的原因。
Q3 · 系统上线三个月,误杀率悄悄上升。最可能的原因与第一动作是?
✔ 正确。§3 讲得很清楚:上线后模型权重不会自己变,变的是输入分布——分数整体抬高,老阈值开始成片误杀。第一动作是对比近期分数与基线(均值超 3σ 即漂移报警)、排查相机/光照/物料、用近期数据重标定阈值;重训是最后的手段,不是第一反应。
✘ 回看 §3"上线之后:阈值不是一劳永逸"。权重不会自己坏,先怀疑分布漂移(换原料、镜头脏了、光照变化);而盲目把阈值调到"不报警为止"只是把误杀换成看不见的漏检,更危险。正确顺序:查分数分布 → 查环境 → 重标定阈值 → 必要时才重建库。
Q4 · 训练集号称"全正常",实际混入了少量缺陷样本。这对 one-class 方法意味着什么?
✔ 正确。§5 第 ② 条"隐形杀手":one-class 的全部前提是训练集纯净。混入的缺陷会进 memory bank / 被学生网络当正常拟合,同类缺陷的异常分数被拉低 → 系统性漏检;而如果离线测试集恰好没覆盖这类缺陷,AUROC 看不出任何异样——它不报错,只在产线上安静地放行坏品。
✘ 回看 §5 第 ② 条:one-class 方法既不会"自动忽略"(它没有缺陷的概念,只会把见过的都当正常),也不会报错(数值上一切正常)。它会认真地把缺陷学成正常,然后漏检——这正是它被称为"隐形杀手"的原因:建库前的数据必须人工复核。
