缺陷检测课程 · 第 08 课

特征嵌入类方法(工业界主流)

一次训练都不做——用 ImageNet 预训练特征给"正常"建档案,新样本查档案看偏不偏。这是当今产线上的默认答案。

0 快速回顾

本课要收割前面埋下的两颗种子,并接住上一课留下的难题:

  • 第 02 课的姿势③"纯特征提取":迁移学习的三种姿势里最省事的一种——骨干冻结,连任务头都不接,直接抽中间层特征做统计建模,一次训练都不做。当时说"到第 8 课它就是主角",现在兑现。
  • 第 02 课的感受野:特征图上每个位置对应原图的一块区域;浅层看细节、深层看语义。本课马上用它把整张图变成一张"patch 特征网格"。
  • 第 07 课重构类的命门:一是网络泛化太好,把没见过的缺陷也"顺手"重构了出来,差异图不亮;二是在像素空间里比差异,光照抖动、噪声、纹理错位这些无害失真全都会假报警。本课的方法根本不重构图像——从源头绕开这两条命门。

1 核心转念:别在像素里比,去特征空间比

上一课判断异常的逻辑是"重构一张图,在像素空间对比差异"。但像素是个糟糕的比较空间:同一个正常工件连拍两张,光照抖一点、传感器噪声换一批、金属纹理的颗粒错开半个像素,像素差就能大到和真缺陷一个量级。在这样的空间里画"正常 / 异常"的分界线,注定摇摇晃晃。

本课的转念只有一句话:换到特征空间去比。第 02 课说过,ImageNet 预训练 CNN 的中间层特征是一部"现成的视觉词典":卷积加池化天然抹平小噪声和小位移(对噪声鲁棒),层层组合又让特征带上语义——边缘、纹理、部件(带语义)。两个"看上去一样"的正常区域,哪怕像素相差不小,特征向量也几乎重合;而一道划痕的特征,会明显偏离所有正常纹理的特征。判断"偏不偏",在这个空间里稳得多。

把图像切成 patch 网格

具体怎么把一张图变成一组可比较的特征?答案是按 patch(小块)来看。但不是真的把图裁成小块逐个送进网络——而是整张图过一次冻结的骨干网络,取中间层特征图。特征图的空间尺寸是 h×w(比如 28×28),每个空间位置是一个 C 维向量。回收第 02 课的感受野:这个位置的向量,描述的正是原图上以它为中心的一小块区域。于是一张图 = h×w 个 patch,每个 patch 一个特征向量,天然排成网格。

多层拼接:细节 + 语义两只眼

用哪一层的特征?小划痕需要浅层的高分辨率细节,大面积污染需要深层的大视野语义——所以标准做法是取两三个中间层(如 ResNet 的 layer2、layer3),在同一位置对齐后拼接成一个更长的向量:细节和语义两只眼一起看。太深的层反而少用:它们偏向 ImageNet 的分类语义("这是猫还是狗"),对工业纹理帮助不大。

"零训练"的确切含义

从这里到本课结束,不会再出现"训练"两个字:骨干是冻结的,没有损失函数,没有梯度下降。接下来三个方法(SPADE → PaDiM → PatchCore)做的全部事情只有两类:统计(算均值、方差)或存储与检索(建库、查库)。范式从"训练一个懂缺陷的模型",变成了"用一个懂图像的模型,给正常建档案"——这就是它们能在产线上"几十张正常样本、几分钟建档开工"的根本原因。

2 最朴素的实现:SPADE 的"检索即检测"

有了 patch 特征,最朴素的做法一步就能想到:把所有正常样本的所有 patch 特征,原封不动存进一张大表——记忆库(memory bank)。"正常"的定义,就是这张表本身:凡是表里出现过(或和表里某条很像)的,都算正常。

推理时,新图像的每个 patch 特征去库里查最近邻:离它最近的那条库记录有多远,这个距离就是该 patch 的异常分。距离小,说明"库里见过长这样的",正常;距离大,说明"正常档案里找不到像它的",异常。把每格分数按位置铺回去是像素级热力图;取全图最大分,是图像级分数。这条"检索即检测"的路线,源头就是 SPADE(它还配了一步图像级预筛:先用全局特征找出最像的 K 张正常图,只在它们的 patch 里检索)。

patch 异常分 = 该 patch 特征到记忆库的最近邻距离 分 ≈ 0 → 库里有几乎一样的 → 正常 分很大 → 全库都不像它 → 异常 图像级分数 = 全图 patch 分的最大值 # 一处异常即 NG

思想干净,但直接上产线会撞上两个工程问题:

问题① 库太大,查得太慢

一张 224×224 的图就有近千个 patch;几百张正常图攒下来,库里是几十万到上百万条特征。

推理时每个 patch 都要和全库算距离。产线要毫秒级,这种查法撑不住。

问题② "正常"是分布,不是点

同一位置(比如"螺丝孔左上角")在不同正常样本上的特征天然有波动:有的维度晃得厉害,有的纹丝不动。

只拿"最近的一个点"量距离,把这些波动形状的信息全丢了。

接下来的两个方法,各接走一个问题:PaDiM 把"点的集合"压缩成"分布",解决问题②;PatchCore 把"全量库"压缩成"核心子集",解决问题①——并顺手成为当今的默认首选。

3 PaDiM:给每个位置建一份高斯档案

PaDiM 的思路:不存点了,给 patch 网格的每个位置建一份统计档案。前提是工件在图里的摆放是对齐的——位置 (i, j) 在每张图里都对应工件的同一个部位。

建档:拿 N 张正常图,收集它们在位置 (i, j) 的 N 个特征向量,估计均值 μij 和协方差 Σij——一个多维高斯分布,完整描述了"这个部位的正常长什么样、往哪些方向晃、晃多大"。h×w 个位置,h×w 份档案,这叫位置感知。

打分:新样本在位置 (i, j) 的特征 x 偏离档案多远,用马氏距离(Mahalanobis distance)来量。这是本课第一个需要原子拆解的概念。

原子拆解:马氏距离——按分布的形状量距离

为什么不用熟悉的欧氏距离?因为欧氏对每一维一视同仁,而"正常波动"恰恰不是各维平等的:

  • 各维尺度不同:有的特征维天生方差大,偏离 2 只是寻常波动;有的维极其稳定,偏离 0.5 都很反常。
  • 维度之间相关:维度 A 高时维度 B 往往也高。"顺着相关方向"的偏离很常见,"逆着"同样大小的偏离才稀奇。

马氏距离的做法一句话说清:先把分布"揉圆"(白化),再量普通的欧氏距离。每一维除以自己的标准差(消掉尺度差异),再旋转消掉维度间的相关,椭圆形的正常分布就变成了标准圆;在这个圆的世界里,普通距离才公平。公式 dM(x) = √((x−μ)T Σ−1 (x−μ)),其中 Σ−1 干的就是"揉圆"这件事。

最小数值例子(取对角协方差,先不管相关): 档案:μ = [0, 0],两维方差 = [4, 1](标准差 = [2, 1]) 新样本 x = [2, 0]: 欧氏 = √(2² + 0²) = 2.0 马氏 = √(2²/4 + 0²/1) = √1 = 1.0 # 第一维本来就爱晃,偏 2 只是 1 个标准差 换成 x = [0, 2]: 欧氏 = √(0² + 2²) = 2.0 # 欧氏眼里:和上面一样远 马氏 = √(0²/4 + 2²/1) = 2.0 # 稳定的第二维上偏 2 = 2 个标准差,反常得多

同样"偏 2":落在爱晃的维度上不算事,落在稳定的维度上就是警报。马氏距离把"这个位置的正常波动范围"考虑进了距离本身——这正是 SPADE 问题②想要的答案。每个位置算一个马氏距离,铺成热力图;全图取 max 得图像分。

PaDiM 的命门:位置对齐

档案是按位置建的。工件平移或旋转几个像素,位置 (i, j) 对应的部位就变了——拿"螺丝孔"的特征去查"平面区"的档案,满图都是假警报。有夹具定位、拍摄严格对齐的产线用它没问题;摆放随意的场景,就要看下一位主角了。(另外,每个位置存一份 μ 和 Σ 内存不小,实际实现要随机抽取一部分特征维降维。)

4 PatchCore:当今的默认首选

PatchCore 回到 SPADE 的"库 + 检索"路线——检索天然不挑位置——然后用两个改进把这条路线做到又快又准,从 2022 年发表至今一直是工业界新任务的默认起点。先看全景,再逐步拆:

STEP 1
建全局记忆库
所有正常 patch 特征
进同一个库,不记位置
→
STEP 2
coreset 贪心降采样
选 1%-10% 的代表点
覆盖整个分布
→
STEP 3
kNN 打分
每个 patch 查近邻
距离即分数,全图 max 即图像分

第①步:全局 memory bank——对错位天然鲁棒

所有正常图的所有 patch 特征进同一个全局库,不记录位置。查询时,一个 patch 可以和库里任何位置的特征匹配:工件挪了半厘米,"螺丝孔"的 patch 照样能匹配上库里别的图的"螺丝孔"特征。PaDiM 的对齐命门,在这里从结构上就不存在。(细节:PatchCore 还会把每个位置和它的邻域聚合一次,让 patch 特征带上一圈上下文;课程里记住"全局库"这个主设计即可。)

第②步:coreset 贪心降采样——1% 的点守住 100% 的疆域

全局库继承了 SPADE 的老毛病:太大。但库里大量特征是冗余的——正常纹理翻来覆去就那几种,成千上万条几乎重合。coreset 的目标:选出一小撮"代表点",使库里任何一条特征到最近代表点都不远——用 1%-10% 的点,保住对整个分布的覆盖。

怎么选?贪心的最远点采样,规则一句话:每一轮,选"到已选集合的最近距离"最大的那个点。拿 5 个二维点手推一遍(选 3 个,从 P0 起步):

点:P0=(0,0) P1=(0.1,0) P2=(5,5) P3=(5,5.1) P4=(10,0) 第 1 轮:起点 P0 入选 已选 {P0} 第 2 轮:各候选点到 {P0} 的距离 P1=0.10 P2=7.07 P3=7.14 P4=10.00 → 最远的是 P4,入选 已选 {P0, P4} 第 3 轮:各候选点到 {P0, P4} 的最近距离 P1 = min(0.10, 9.90) = 0.10 P2 = min(7.07, 7.07) = 7.07 P3 = min(7.14, 7.14) = 7.14 → 最远的是 P3,入选 已选 {P0, P4, P3} 结果:{P0, P4, P3} 分守左下、右下、右上三块疆域 P1 和 P0 几乎重合,纯冗余,永远轮不到它

每一步都在填补"当前覆盖最薄弱的空洞"。这正是随机抽样做不到的:随机按密度抽,会把密集区抽一大把、把稀疏但重要的边界点漏掉——而"正常的边界"恰恰是异常检测最需要守住的地方。

第③步:推理——查近邻,距离即分数

新图的每个 patch 特征到精简库里查 k 近邻(k 取 1 或很小的数),最近邻距离(PatchCore 还做一步邻域重加权,让"连它的近邻都很孤僻"的点分数更高)就是 patch 分;分数铺回位置得热力图,全图取 max 得图像分。库缩小了一两个数量级,再配上近似最近邻索引,推理毫秒级。

成绩:MVTec AD 基准上图像级 AUROC 99%+,像素级定位同样顶尖。工业界爱它的理由,每一条都很实际:

  • 零训练:不碰梯度、没有调参地狱;换一条产品线 = 重建一次库,几分钟的事。
  • 吃得少:几十张正常样本就能用,极端情况十几张也有像样的精度——完美适配"缺陷样本稀缺、正常样本管够"的工业现实(第 04 课的核心矛盾)。
  • 对错位鲁棒:全局库,见第①步。
  • 可解释:某个 patch 分数高,可以反查"它最像库里哪个正常 patch、差多远"——给产线工程师一个看得见的证据,而不是一个黑盒分数。

7 局限与边界

特征嵌入类不是万能钥匙,它的边界清楚地写在它的前提里:

  • 域差距:整套方法压在"ImageNet 特征能描述你的图像"这一条上。自然图像练出的词典,遇到差得太远的成像(X 光、超声、特殊材质的微观纹理)会"词穷"——正常和异常在特征空间里挤成一团,查档案就失灵。补救方向:换领域更近的骨干,或用自监督预训练。
  • 对齐与几何变化:PaDiM 对错位高度敏感;PatchCore 对平移鲁棒,但大角度旋转、剧烈尺度变化仍会让 patch 特征对不上库。
  • 逻辑异常无能为力:零件每一块都正常,但装错了位置、装反了、少装了一个——每个 patch 都能在库里查到近亲,分数全低,整图却是次品。局部外观检索,管不了全局逻辑;MVTec LOCO 数据集专考这类题,第 13 课再展开。

✓ 自我检验

四道题,检查本课的核心概念是否立住了。

Q1 · 特征嵌入类方法号称"零训练",它靠什么代替了训练?
✔ 正确。§1 的核心:骨干冻结,全程没有损失函数和梯度下降;所谓"建档案"只是算均值/协方差(PaDiM)或存库+检索(SPADE / PatchCore)。预训练特征本身已经够好,方法只负责"查"。
✘ 回看 §1 的"'零训练'的确切含义":这族方法从头到尾不做梯度下降,靠的是 ImageNet 预训练特征 + 统计/检索,和增强或学习率都无关。
Q2 · 马氏距离比欧氏距离多考虑了什么?
✔ 正确。§3 的数值例子:方差 [4,1] 时,x=[2,0] 的欧氏是 2.0、马氏只有 1.0——在爱晃的维度上偏 2 不稀奇;换到稳定维度马氏立刻翻倍。马氏 = 先按 Σ⁻¹"揉圆"分布,再量距离。
✘ 回看 §3 的原子拆解:欧氏对每一维一视同仁;马氏把"各维方差不同 + 维度间相关"(分布形状)算进距离,先白化再量。和维度数量、位置坐标无关。
Q3 · coreset 贪心降采样,每一轮选进来的是什么点?
✔ 正确。§4 第②步的手推:第 2 轮选了离 P0 最远的 P4,第 3 轮选了 P3;和 P0 几乎重合的冗余点 P1 永远轮不到。每一步都最大化覆盖——这叫最远点采样。
✘ 回看 §4 第②步的手推例子:规则是"谁离已选集合最远,谁入选"。选最近的等于反复挑冗余点;随机抽会按密度采样,漏掉稀疏但关键的分布边界。
Q4 · PatchCore 比 PaDiM 更能容忍"工件摆放偏移",根本原因是?
✔ 正确。§3 结尾与 §4 第①步的对照:PaDiM 拿"螺丝孔"特征查"平面区"档案会满图误报;PatchCore 的全局 memory bank 不记录位置,错位后"螺丝孔"照样匹配上库里的"螺丝孔"。
✘ 和维度高低、数据增强都无关。回看 §4 第①步:全局库不记录位置,这个结构性设计让错位天然不致命;而 PaDiM(§3)的档案按位置绑定,错位就是查错档案。
